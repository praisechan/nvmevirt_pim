## 2. Model Recap

The INFLASH_PIM compute-read model treats each 4 KB read as a single-LUN operation.
With 512 independent LUNs striped round-robin across 16 channels × 32 LUNs/ch,
N requests issued simultaneously saturate `ceil(N / 512)` sequential rounds.

Each round charges:

| Component | Value |
|-----------|-------|
| NAND read latency `tR` | 30 µs |
| Channel command/result transfer `t_cmd` | 8 µs |
| **Round total `t_round`** | **38 µs** |

**Prediction:**

$$T_{\text{model}}(N) = 38\,\mu\text{s} \times \left\lceil \frac{N}{512} \right\rceil$$

This is the primary metric against which measured `t_endtoend_ns` is compared.

### Calibration knobs (adjust after microtest)

| Macro | Current value | Purpose |
|-------|---------------|---------|
| `FW_CH_XFER_LATENCY` | 0 | Channel overhead per 32-LUN batch |
| `COMPUTE_RESULT_SIZE` | 64 B | Per-LUN result size (controls channel bandwidth charge) |

## 7. Threats to Validity

1. **LUN-as-plane abstraction.**  
   NVMeVirt models each LUN as an independent plane. Real in-flash compute would
   expose intra-plane (same die) resource contention not captured here. The emulation
   therefore represents an optimistic upper bound on parallelism.

2. **Single-host software stack overhead.**  
   io_uring submission and CQE reaping on the same host that runs NVMeVirt introduces
   software paths not present in a real PCIe+NAND stack. Measured latencies include
   kernel scheduling jitter for the NVMeVirt polling threads.

3. **No real PCIe DMA.**  
   The `INFLASH_COMPUTE` path sets `interleave_pci_dma = false`, eliminating the DMA
   from the emulated latency model. On real hardware, even a small result (~64 B) still
   traverses the PCIe link, adding ~1–2 µs not modelled here.

4. **Memmap capacity constraints.**  
   The 16 GB memmap at 96 GB supports ≈ 4 M pages (16 GB / 4 KB). The sweep reaches
   N=4096 pages, well within capacity, but prepopulation of all LUNs requires at
   least 512 writes before valid mapping data exists.

5. **Round-robin striping assumption.**  
   The model assumes NVMeVirt's `advance_write_pointer` distributes consecutive LPNs
   round-robin across all 512 LUNs. If the actual striping differs (e.g. per-channel
   granularity), the same-LUN test (LPN 0 vs LPN 512) may not target the expected LUN.
   Verify with `dmesg` traces if needed.
